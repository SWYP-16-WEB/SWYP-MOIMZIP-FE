# Git Convention

이 문서는 브랜치 전략과 명명 규칙, PR 제목 규칙과 작성 요령을 정리하는 문서입니다. 커밋 메시지 규칙은 [`commit.md`](./commit.md)를 참고하세요.

## Branch

### 브랜치 전략

| 브랜치      | 역할                                                           |
| ----------- | -------------------------------------------------------------- |
| `main`      | 배포 브랜치. `develop`에서 검증된 내용만 머지한다.             |
| `develop`   | 개발 통합 브랜치. 작업 브랜치는 여기서 만들고 여기로 머지한다. |
| 작업 브랜치 | 이슈 단위 작업 브랜치. `develop`에서 분기한다.                 |

### 이름 규칙

`{접두사}/#{이슈 번호}/{작업 내용}` 형태로 만든다.

```txt
init/#1/project-setting
feat/#12/login-page
fix/#20/invite-card-layout
```

- 접두사는 [`commit.md`](./commit.md)의 커밋 접두사를 그대로 따른다.
- 작업 내용은 영어 소문자 케밥 케이스로 쓴다.
- 브랜치를 만들기 전에 GitHub 이슈를 먼저 생성하고, 그 번호를 브랜치 이름에 넣는다.

## Pull Request

### 제목

`[접두사] 작업 내용` 형태로 작성한다. 접두사는 [`commit.md`](./commit.md)의 커밋 접두사와 동일하되 첫 글자만 대문자로 쓴다.

```txt
[Init] 프로젝트 초기 세팅
[Feat] 로그인 페이지 구현
[Fix] 초대장 카드 레이아웃 수정
```

### 템플릿 및 작성 요령

PR을 열면 [`.github/pull_request_template.md`](../../.github/pull_request_template.md)가 본문에 자동으로 채워진다. 각 항목은 아래 기준으로 작성한다.

| 항목           | 작성 요령                                                                       |
| -------------- | ------------------------------------------------------------------------------- |
| 🔗 연관된 이슈 | `closes #이슈번호`로 작성한다. 머지되면 이슈가 자동으로 닫힌다.                 |
| 📝 작업 내용   | 수행한 작업을 번호로 나열하고, 각 작업에서 무엇을 왜 이 방식으로 했는지 적는다. |
| 💬 공유 사항   | 리뷰어가 알아야 할 점, 고민했던 부분, 논의가 필요한 부분을 적는다.              |
| 📸 스크린샷    | UI 변경이 있으면 변경 전/후 화면을 첨부한다. 없으면 비워둔다.                   |
| ETC            | 그 외 공유할 사항을 적는다.                                                     |

팀원이 별도 설명 없이 PR만 읽어도 맥락을 파악할 수 있는 수준으로 작성한다.

### 자동화

PR을 열면 GitHub Actions가 아래 작업을 자동으로 수행한다.

| 워크플로우                                               | 동작                                                                                                                                                                                  |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`pr-triage.yml`](../../.github/workflows/pr-triage.yml) | 작성자를 assignee로 지정하고, 작성자를 제외한 팀원에게 리뷰를 요청하고, 작성자 라벨을 붙인다. PR 제목 접두사(`[Feat]` 등)에 맞는 라벨을 붙이며, 제목을 수정하면 라벨도 다시 계산한다. |
| [`ci.yml`](../../.github/workflows/ci.yml)               | `develop`, `main` 대상 PR에서 `pnpm lint`, `pnpm build`를 실행하고 결과를 PR 코멘트로 남긴다. 실패하면 체크도 실패한다.                                                               |
| [`deploy.yml`](../../.github/workflows/deploy.yml)       | `main`에 push되면 `seunghye-rain/SWYP-MOIMZIP-FE` fork의 `main`을 동일하게 강제 동기화한다. 배포는 fork에 연결된 배포 서비스가 담당한다.                                              |

팀원이 바뀌면 `pr-triage.yml`의 `TEAM`(GitHub 아이디 → 사람 라벨)을 수정한다.

### 머지

- 작업 브랜치의 PR은 `develop`을 대상으로 연다.
- 머지 전 로컬에서 `pnpm lint`, `pnpm build`가 통과하는지 확인한다. CI가 실패한 PR은 머지하지 않는다.
