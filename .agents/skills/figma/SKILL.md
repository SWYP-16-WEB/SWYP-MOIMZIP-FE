# Figma 디자인 구현

Figma 디자인을 기존 프로젝트 구조와 디자인 토큰에 맞춰 코드로 반영합니다. 요청한 화면·컴포넌트·토큰 범위만 작업하며, Figma 파일 편집이나 별도 예시 화면 생성을 포함하지 않습니다.

## 참조 문서

아래 링크는 이 스킬 파일 기준 상대 경로입니다. 명령은 저장소 루트에서 실행합니다.

- [프로젝트 작업·검증 절차](../../../AGENTS.md)
- [디자인 토큰과 사용 예시](../../../docs/design/design-tokens.md)
- [코딩·스타일링 컨벤션](../../../docs/conventions/dev-convention.md)
- [폴더 구조·의존성](../../../docs/architecture/fsd.md)
- [검증 도구](../../../docs/conventions/tooling.md)

토큰 매핑 전 [컬러 정의](../../../src/styles/color.token.css), [폰트 정의](../../../src/styles/font.token.css), [클래스 병합 규칙](../../../src/shared/utils/cn.ts)도 확인합니다. 토큰 이름과 값은 이 스킬에 복사하지 않고 현재 문서·코드를 기준으로 판단합니다.

## 트리거

- Figma 프레임·노드에 맞춘 페이지·컴포넌트 구현 또는 스타일 수정
- 디자인 시스템의 컬러·타이포그래피를 프로젝트 토큰에 추가·갱신
- 구현 결과와 Figma 디자인의 차이 확인

## 해야 할 일

1. 요청 범위를 확인합니다. 화면 구현, 기존 UI 수정, 토큰 세팅 중 무엇인지 구분합니다. 토큰만 요청받았다면 컴포넌트나 미리보기 라우트를 추가하지 않습니다.
2. 제공된 Figma 파일·노드를 확인하고 사용 가능한 Figma 도구로 필요한 디자인 컨텍스트, 스크린샷, 스타일·변수를 조회합니다. 도구가 요구하는 전용 스킬과 세션 절차를 따릅니다. 대상이나 접근 정보가 부족하면 링크·노드 정보를 요청하고, 디자인 값을 추측하지 않습니다.
3. 디자인의 컬러·타이포그래피·에셋을 현재 토큰과 기존 구현에 매핑합니다. 도구가 생성한 코드는 참고 자료로 사용하고 프로젝트 구조에 맞춰 반영합니다. 디자인 시스템과 화면의 값이 다르면 차이를 확인한 뒤 적용하며, 토큰을 임의로 덮어쓰지 않습니다.
   - 도구가 주는 에셋 URL은 임시 주소이므로 프로젝트에 내려받아 연결합니다.
   - 아이콘은 `src/shared/assets/svg/`에 영어 kebab-case 파일명으로 넣고 `pnpm build:icons`로 컴포넌트를 만듭니다. 장식용 배경 이미지처럼 색을 바꿀 필요가 없는 에셋은 `public/`에 둡니다. 생성 규칙은 `tooling.md`를 따릅니다.
4. 컬러는 기존 역할별 토큰을, 타이포그래피는 기존 `@utility` 조합 클래스를 우선 사용합니다. 간격·크기·둥글기는 컨벤션의 rem 임의값을 사용합니다. 새 타이포그래피를 추가하면 폰트 정의, `cn`의 타이포그래피 그룹, 디자인 토큰 문서를 함께 갱신합니다.
5. 화면은 `views`, 사용자 행동 UI는 `features`, 도메인 데이터 표시 UI는 `entities`, 도메인과 무관한 공용 UI는 `shared/ui`, 라우팅·연결은 `app`의 책임에 맞춥니다. 배치 기준은 [구조 문서](../../../docs/architecture/fsd.md)와 `project-rule` 스킬을 따르고, 화면은 `app-page`, 공용 UI는 `shared-components` 스킬을 함께 읽습니다. 기존 컴포넌트·폰트·에셋과 서버 연동 방식을 재사용합니다. 반응형 동작과 인터랙션은 요청·명세와 기존 패턴에 근거해 구현합니다.
   - 전 화면 공통 배경과 페이지 여백은 루트 레이아웃과 `src/styles/layout.css`에 이미 적용되어 있으므로 화면마다 다시 구현하지 않습니다.
   - 시안이 확정 전이면 화면에 필요한 범위만 구현하고, 시안 전체의 공용 컴포넌트를 미리 만들지 않습니다.
6. 변경 범위에 맞춰 검증하고 문서도 갱신합니다. 프로젝트 Figma 링크는 저장소 문서나 코드에 새로 기록하지 않습니다. 커밋·PR·머지와 Figma 파일 수정은 별도 요청 범위에서만 수행합니다.

## 점검해야 할 내용

- 토큰명이 실제 CSS 정의와 일치하며, 임의의 별칭이나 유사한 다른 색으로 대체하지 않았는지 확인합니다.
- 타이포그래피의 크기·굵기·행간·자간과 폰트 로딩을 확인합니다. 클래스 덮어쓰기는 `cn`의 병합 동작도 확인합니다.
- 화면을 수정했다면 디자인과 렌더링 결과를 비교하고 대상 화면의 반응형 배치·주요 동작을 확인합니다. 이미지·아이콘은 원본 비율과 배치, 로컬 에셋 연결을 확인합니다.
- 토큰만 수정했다면 관련 Tailwind 클래스·variant의 CSS 생성과 값 매핑을 확인합니다. 검증을 위해 제품 화면을 추가하지 않습니다.
- 코드 변경은 `pnpm format:check`, `pnpm lint`, `pnpm build`를 실행합니다. 문서만 변경했다면 변경 문서의 포맷과 참조 경로를 확인합니다.
- 디자인 정보 부족, 문서·코드 불일치, 실행하지 못한 검증은 결과에 명시합니다.
